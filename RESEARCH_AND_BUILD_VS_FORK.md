# Research and build-versus-fork decision

Research date: 2026-11-02. Public repository pages, selected source files and directory listings were inspected through the web. These projects were **not installed, executed, penetration-tested, or exhaustively audited**. Activity below means visible repository/PR/release surfaces, not a verified maintenance SLA or commit-frequency measurement. No third-party source code was copied.

| Project and license observed | Architecture / financial relevance | Testing and activity observed | Excel / flexibility / security assessment | Decision |
|---|---|---|---|---|
| [Saleor](https://github.com/saleor/saleor), BSD-3-Clause | Python commerce API; discount module directory inspected | Open PR/issues and Actions visible; test execution/quality not verified | This review did not verify a seller contribution XLSX workflow; modular commerce API would require substantial adaptation. Deployment security not audited. | Too broad for local workbook-first tool |
| [WooCommerce](https://github.com/woocommerce/woocommerce), GPL-2.0 shown | PHP/WordPress; [WC_Tax source](https://raw.githubusercontent.com/woocommerce/woocommerce/trunk/plugins/woocommerce/includes/class-wc-tax.php) separates inclusive/exclusive tax and controls rounding | [Tests directory](https://github.com/woocommerce/woocommerce/tree/trunk/plugins/woocommerce/tests) inspected; active PR surface; no tests run | Rich commerce extension architecture, but no verified seller cost-floor workbook flow. WordPress deployment introduces a different operational stack. | No GPL source copied into MIT engine |
| [Django Oscar](https://github.com/django-oscar/django-oscar), BSD-3-Clause | Python/Django policy objects; [prices.py](https://raw.githubusercontent.com/django-oscar/django-oscar/master/src/oscar/apps/partner/prices.py) explicitly represents unknown tax and separate gross/net prices | [Tests](https://github.com/django-oscar/django-oscar/tree/master/tests) directory inspected; PR surface visible; coverage not measured | Useful separation of pricing policies; native bulk profit-floor XLSX and deployment readiness not established | Architectural reference only |
| [Medusa](https://github.com/medusajs/medusa), MIT core; enterprise materials separately licensed | TypeScript modular commerce; [pricing module](https://github.com/medusajs/medusa/tree/develop/packages/modules/pricing) inspected; repository describes PostgreSQL integration tests | Integration-test architecture described by README; no execution; open issues/PRs visible | Extensible pricing/promotions; exact XLSX profitability calculations and operational security unverified. Requires substantially more infrastructure | Do not integrate for initial local Python release |
| [PrestaShop](https://github.com/PrestaShop/PrestaShop), OSL-3.0 core / AFL-3.0 modules per [license file](https://raw.githubusercontent.com/PrestaShop/PrestaShop/develop/LICENSE.md) | PHP commerce platform; repository architecture inspected at directory level | [Tests directory](https://github.com/PrestaShop/PrestaShop/tree/develop/tests), security and PR surfaces visible; no tests run | Merchant platform rather than standalone audited contribution solver; import/export details and deployment security not verified | No copying; exact per-file license review would be required before reuse |

Searches included marketplace repricers, commission/profitability calculators, bulk pricing and Iranian seller tools. The Iranian search surfaced [digikala-mcp](https://github.com/sepehr071/digikala-mcp), a read-only product/offer retrieval project, not verified seller cost accounting. It was not evaluated as an engine dependency and no fee rules were imported. No suitable independently verified Iranian seller-profitability engine was identified in this limited search. This is not a claim that none exists.

Build independently. The required contract is unusually strict: missing-versus-zero, exact Decimal floor solving, per-SKU audit, subsidy/tax semantics, no remote product-cost service, and a downloadable workbook. Forking a complete commerce platform would bring unrelated persistence, checkout, authentication, licensing and migration obligations. MIT was selected for the new original source to permit extension and commercial reuse with notice preservation. Runtime dependencies keep their own licenses. Recheck upstream licenses and dependency notices before redistributing bundled runtimes.
